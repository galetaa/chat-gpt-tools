# Исследование ускорения ChatGPT в Safari

Проверено 20 августа 2026 года. Цель — ускорять длинные беседы, не вмешиваясь в отправку сообщений, авторизацию и сохранённую на сервере историю.

## Что включено

### Раннее сокращение conversation JSON

Основной оптимизатор ChatGPT Tools работает до построения интерфейса: перехватывает только GET-запросы конкретной беседы, сохраняет активную ветку и передаёт ChatGPT последние N видимых групп сообщений. Это уменьшает объём React-состояния и число создаваемых DOM-узлов. Любая незнакомая схема или ошибка обрабатывается fail-open — страница получает исходный ответ.

### Пересборка текущего чата

Долгая открытая сессия продолжает накапливать уже отрисованные сообщения после первоначальной загрузки. Команда `Re-compact Current Chat` перезагружает активную вкладку, чтобы раннее сокращение снова применилось к актуальной беседе. История аккаунта при этом не удаляется и не изменяется.

### Дешёвое наблюдение за DOM

Сворачивание длинных пользовательских запросов обрабатывает добавленные узлы пакетно через `requestAnimationFrame`. В 1.2 observer больше не подписан на `characterData`: пользовательские запросы появляются готовыми, а посимвольное наблюдение за потоковым ответом ассистента было лишней работой. Для свёрнутого текста применяется только `contain: paint`, без изменения раскладки всей ленты.

### Событийная навигация

Переходы внутри SPA определяются через `pushState`, `replaceState`, `popstate` и `hashchange`. Постоянный таймер опроса URL не используется.

## Что исследовано, но не включено

### `content-visibility: auto` для сообщений

Спецификация CSS Containment допускает пропуск layout и paint для невидимого содержимого, сохраняя его доступность для поиска и фокуса. Однако в актуальном Safari/WebKit зарегистрирована воспроизводимая проблема: повторный скролл элементов с `content-visibility:auto` вызывает заметные рывки. Поэтому оптимизация не подходит для Safari-сборки сейчас.

Источники: [CSS Containment Level 2](https://www.w3.org/TR/css-contain-2/), [WebKit bug 318216](https://bugs.webkit.org/show_bug.cgi?id=318216).

### Скрытие старых сообщений и подстановка placeholder

Проект [chatgpt-virtualiser](https://github.com/NathanBarnard/chatgpt-virtualiser) скрывает старые сообщения через `display:none`, оставляет заполнитель высоты и раскрывает узлы по мере прокрутки. На очень длинных чатах это может снизить стоимость отрисовки, но прямое изменение управляемого React DOM способно нарушить поиск по странице, копирование диапазона, ветвление, восстановление позиции и будущие изменения разметки ChatGPT. Для расширения с полной поддержкой такой риск неприемлем.

### Подмена потоковых API и перенос истории из React

Проект [gpt_performance_optimizer](https://github.com/sergey-pimenov/gpt_performance_optimizer) дополнительно перехватывает `ReadableStream`, `EventSource`, bootstrap JSON и хранит полную беседу в `localStorage`, отображая старые сообщения вне React. Это более глубокая и хрупкая подмена внутренней архитектуры сайта, увеличивающая риск несовместимости и объём локально сохранённых данных. ChatGPT Tools ограничивается узким перехватом двух conversation endpoints.

## Практики вне расширения

Официальные рекомендации OpenAI при общей медленной работе ChatGPT: проверить status page, очистить cache/cookies, попробовать другой браузер, отключить конфликтующие расширения и закрыть лишние вкладки или программы. Автоматически выполнять эти действия нельзя: они затрагивают сессию пользователя и другие сайты. См. [Why is my ChatGPT taking so long to respond?](https://help.openai.com/en/articles/9047779-why-is-my-chatgpt-taking-so-long-to-respond).

## Принцип отбора

Включается только оптимизация, которая локальна, обратима, не отправляет данные наружу и при сбое оставляет ChatGPT работоспособным. Любая техника, требующая владеть React DOM, менять глобальную семантику streaming API или дублировать полную историю в новом хранилище, остаётся экспериментальной и не входит в основную сборку.
